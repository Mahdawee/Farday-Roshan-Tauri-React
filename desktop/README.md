# فردای روشن — آغاز بازسازی دسکتاپ

این پوشه نسخهٔ اولیه‌ای در کنار برنامهٔ PHP است، نه جایگزین آمادهٔ استفاده. برنامه و دیتابیس قبلی دست‌نخورده‌اند. **از این نسخه برای معلومات واقعی شرکت استفاده نکنید:** احراز هویت، ورود اطلاعات قبلی، مدیریت کامل اسناد، تقویم شمسی برای ثبت و سایر شیت‌ها تکمیل نشده‌اند.

## آنچه پیاده‌سازی شده

- React/TypeScript و رابط راست‌چین با فونت محلی؛ لایهٔ `Store` میان رابط و روش دسترسی به داده.
- Tauri 2 و Rust/SQLx با SQLite جداگانه در پوشهٔ دادهٔ برنامهٔ کاربر، همراه migration و کلید خارجی فعال.
- ثبت اولیهٔ مشتری، فروش و رسید، فهرست، و کارت حساب بر اساس فروش قرضه و رسیدهای مؤثر؛ امانت در کارت نمایش داده می‌شود اما از بدهی کم نمی‌شود.
- مبلغ و حجم به شکل عدد صحیح مقیاس‌دار نگهداری می‌شوند و مجموع فروش در Rust دوباره محاسبه می‌شود. تاریخ ورودی فعلاً میلادی است.
- سرویس SQLite از فرمان‌های Tauri جدا شده است؛ این فقط یک گام معماری است و هنوز به معنی پیاده‌سازی سرور یا پشتیبانی از PostgreSQL نیست.
- پشتیبان و بازگردانی آزمایشی SQLite: فایل با `VACUUM INTO` ساخته می‌شود؛ بازگردانی فقط نسخهٔ ساختار فعلی را می‌پذیرد، پیش از تغییر یک نسخهٔ ایمنی می‌سازد و همهٔ جایگزینی‌ها را در یک تراکنش انجام می‌دهد. این فایل‌ها رمزگذاری نشده‌اند و نباید تنها نسخهٔ اطلاعات واقعی باشند.
- شناسه‌های مستقل UUID؛ شمارهٔ سند رسمی و تمام فیلدهای نسخهٔ قدیمی هنوز پیاده‌سازی نشده‌اند.

## اجرا

Node.js و npm و ابزار Rust و پیش‌نیازهای Tauri 2 برای سیستم‌عامل مقصد لازم‌اند. در Linux، کتابخانه‌های توسعهٔ WebKitGTK و سایر پیش‌نیازهای رسمی Tauri نیز لازم است. از داخل این پوشه:

```sh
npm ci
npm run tauri dev
```

برای مشاهدهٔ رابط بدون Rust: `npm run dev`؛ مرورگر تنها یک پیش‌نمایش **حافظه‌ای و موقت** با اطلاعات نمونه است. با تازه‌کردن صفحه داده‌ها از بین می‌روند و هیچ ارتباطی با دیتابیس PHP یا SQLite ندارد. نسخهٔ تولیدی وب/API هنوز وجود ندارد.

```sh
npm test
npm run build
python3 tests/schema_test.py
npx playwright install chromium
npm run test:e2e
cd src-tauri && cargo test
```

تست مرورگر فقط پیش‌نمایش موقت را بررسی می‌کند، نه اتصال Tauri و SQLite. تست Rust در GitHub Actions برای Windows تنظیم شده است اما تا زمان اجرای واقعی آن نتیجه‌ای تضمین نشده است.

## گام‌های بعدی و معماری

قوانین حسابداری، سال مالی و انتقال داده باید با نمونهٔ واقعی و حسابدار تأیید شود. برای حالت آنلاین، سرویس مرکزی، مجوزها، لایهٔ ذخیرهٔ سروری و قرارداد API باید جداگانه پیاده‌سازی و آزمایش شوند؛ هیچ همگام‌سازی یا پشتیبانی چندکاربره وجود ندارد. پیش از استفادهٔ واقعی به تست یکپارچهٔ پنجرهٔ Tauri و SQLite، آزمایش بیشتر بازیابی، شماره‌گذاری سند و تطبیق کامل گزارش‌ها نیاز است.

## بازگردانی آزمایشی

بازگردانی فقط فایل `.sqlite3` ساخت همین نسخهٔ دسکتاپ را می‌پذیرد، نه بکاپ SQL مربوط به PHP/MySQL. ساختار جدول‌ها، سابقهٔ migration، صحت SQLite، ارتباطات و بخشی از قواعد مالی بررسی می‌شوند. قبل از جایگزینی، یک فایل ایمنی در پوشهٔ `restore-safety` در پوشهٔ دادهٔ برنامه ساخته و مسیر آن پس از موفقیت نمایش داده می‌شود. در صورت خطا، تراکنش بازگردانده می‌شود؛ فایل ایمنی بدون رمزگذاری باقی می‌ماند. فایل‌های نسخه‌های آینده تا زمان پشتیبانی صریح، رد می‌شوند. اطلاعات پیش‌نمایش مرورگر در این عملیات نقشی ندارند. هنوز نباید از برنامه برای اطلاعات واقعی استفاده کرد.
