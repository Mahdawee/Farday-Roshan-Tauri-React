# فردای روشن — پروژهٔ مستقل نسخهٔ جدید

**وضعیت: اولین بخش آزمایشی در حال ساخت، نه نسخهٔ آمادهٔ استفاده.** این پوشه جدا از PHP ریشه و نمونهٔ فعلی `desktop/` است. هیچ‌کدام تغییر یا حذف نشده‌اند. هدف، ساخت نسخهٔ جدید با React/TypeScript، Tauri 2، Rust/SQLx و دیتابیس متناسب با شیوهٔ واقعی استفاده است؛ نه صرفاً بازسازی ظاهر.

## آنچه فعلاً ساخته شده است

صفحهٔ مشخصات شرکت و ثبت، ویرایش و حذف انواع ماشینری، با بررسی ورودی و تشخیص تغییر هم‌زمانِ نسخهٔ رکورد. صفحهٔ چاپ فقط پیش‌نمایش ساده است، نه قالب رسمی تأییدشده. دیتابیس Tauri محلی و مستقل از نسخه‌های قبلی است (`farday-next.sqlite3` در app-data با شناسهٔ `af.fardayroshan.next.preview`). در مرورگر از دیتابیس استفاده نمی‌شود: داده‌ها فقط در حافظه‌اند و با بارگذاری مجدد پاک می‌شوند.

**فقط برای دادهٔ ساختگی:** ورود و مجوز کاربران، تاریخچهٔ محافظت‌شده، بکاپ/بازیابی و تمام بخش‌های مالی و عملیاتی دیگر هنوز پیاده نشده‌اند. SQLite فعلاً تنها فرض یک دستگاه است. نصب، ارتقا، امضای دیجیتال و کارکرد تعاملی Tauri نیاز به آزمون جداگانه دارند؛ نصب‌کنندهٔ debug در CI در صورت موفقیت بدون امضا و آزمایشی است.

برای پیش‌نمایش مرورگر (Node 22):

```sh
cd farday-next
npm ci
npm run dev
# آزمون و ساخت frontend
npm test
npm run build
# پس از نصب مرورگر Playwright و وابستگی‌های آن
npx playwright install chromium
npm run test:e2e
```

برای desktop به Rust و پیش‌نیازهای Tauri 2 نیاز است؛ `npm run tauri -- dev` برنامه را اجرا می‌کند. بررسی Rust/SQLite و ساخت آزمایشی Windows در workflow `farday-next.yml` انجام می‌شود. آزمون مرورگر جایگزین آزمون تعاملی desktop و نصب‌کننده نیست.

## نتیجهٔ اصلی بررسی

1. نسخهٔ PHP مرجع رفتار و داده است، اما در چند مورد خودش رفتار متناقض یا خطرناک دارد. «عین نسخه» باید با سناریو و نتیجهٔ مورد انتظار تعریف شود؛ کپی کورکورانهٔ یک خطای مالی درست نیست.
2. نمونهٔ فعلی `desktop/` ارزش فنی و آزمون دارد، اما کامل نیست: ورود و مجوز در فرمان‌های واقعی فعال نیست؛ داده‌های PHP وارد نمی‌شوند؛ و دخل دستی آن هم‌ارز دخل قدیم نیست. اجزای آن فقط پس از بررسی و آزمون به پروژهٔ جدید منتقل می‌شوند، نه به شکل کپی کامل و بی‌قید.
3. کاربر هنوز دربارهٔ تک‌دستگاه یا شبکه تصمیم نگرفته است. SQLite برای برنامهٔ محلی روی یک دستگاه مناسب است؛ **چند دستگاه هم‌زمان با فایل مشترک SQLite** راهکار مطمئن جایگزین سرویس مرکزی نیست. فعلاً حالت محلی یک فرض موقت است، نه تصمیم نهایی شبکه.
4. کاربر انتخاب کرده است که **از معلومات تازه آغاز شود**؛ انتقال اطلاعات قبلی در محدودهٔ فعلی نیست. اطلاعات PHP و رفتار آن همچنان با دادهٔ ساختگی برای تطبیق قابلیت‌ها بررسی می‌شود. فایل پشتیبان SQL قدیم پشتیبان SQLite نیست.
5. اطلاعات واقعی، قالب رسمی، امنیت، نتایج حسابداری، چاپ بومی و نصب‌کنندهٔ امضاشده بدون آزمون و تأیید مربوط، آماده اعلام نمی‌شوند.

## دامنه و محدودیت این بررسی

بررسی بر اساس کد مخزن در commit مبنا `0bfb8a5431bb2a90f68510b4b3bdb1876b0e4989`، فایل‌های PHP، schema و seed و نمونهٔ `desktop/` است. در این محیط PHP/MySQL و Rust محلی در دسترس نبودند؛ **نسخهٔ PHP با پایگاه واقعی یا نمونه اجرا نشده** و هیچ خروجی واقعی با نسخهٔ جدید تطبیق نشده است. رفتار واقعی نصب‌های قدیمی ممکن است به خاطر نسخهٔ schema، داده‌ها یا تغییرات نصب‌شده متفاوت باشد. باید با پایگاه آزمایشی و سناریوهای ثبت‌شده اعتبارسنجی شود.

اسناد رسمی فناوری و مراجع فایل‌های پروژه در ادامهٔ سندها ذکر شده‌اند. تا زمان رفع تصمیم‌های باز، معماری مقصد یک پیشنهاد مهندسی است، نه قرارداد حسابداری تأییدشده.
