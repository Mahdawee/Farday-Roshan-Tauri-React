# وضعیت پیاده‌سازی مستقل

این سند وضعیت `farday-next/` را توصیف می‌کند؛ ماتریس ۰۱ وضعیت نمونهٔ قدیمی `desktop/` را ثبت می‌کند و نباید به معنای تکمیل نسخهٔ جدید تلقی شود.

| بخش | وضعیت نسخهٔ مستقل |
|---|---|
| شرکت و ماشینری | فرم و عملیات پایه با SQLite محلی، revision و اعتبارسنجی؛ چاپ رسمی و دسترسی/تاریخچه در انتظار. |
| مشتریان | اطلاعات پایهٔ PHP، جستجو و ۲۵ مورد در صفحه؛ ثبت، ویرایش، حذف، کد دستی یکتا، بدهی اولیهٔ دقیق تا دو اعشار و revision. ذخیرهٔ مقدار بر حسب صدم integer است و به صورت رشته از مرز JavaScript می‌گذرد تا دقت از بین نرود. |
| فروش، رسید و بدهی جاری | **ساخته نشده**؛ ماندهٔ اولیه به عنوان ماندهٔ حساب معرفی نمی‌شود، جمع فروش، فیلتر وضعیت حساب و کارت حساب PHP نیز وجود ندارد. |
| کد مشتری و مقایسه | پیشنهاد خودکار کد PHP وجود ندارد. یکتایی SQLite `NOCASE` تنها حروف ASCII را پوشش می‌دهد، نه تمام قواعد `utf8mb4_unicode_ci` در MySQL؛ قبل از بهره‌برداری باید قاعدهٔ یکسان‌سازی مشخص و آزموده شود. |
| حذف مشتری | فعلاً حذف در نسخهٔ فاقد فروش و رسید انجام می‌شود. قبل از افزودن جدول‌های وابسته، کلید خارجی و سیاست حفظ سابقه/حذف باید در Rust و SQLite تعیین و آزمون شود؛ نباید دادهٔ مالی به صورت تصادفی یتیم یا حذف شود. |
| امنیت و عملیاتی | احراز هویت، مجوز، audit مقاوم، بکاپ، بقیهٔ صفحات، حسابداری تأییدشده، CSV، چاپ رسمی، امضا و تست دستی نصب/ارتقا موجود نیستند. مناسب اطلاعات واقعی نیست. |

مهاجرت `0002_customers.sql` باید اطلاعات شرکت و ماشینری موجود را حفظ کند؛ آزمون Rust یک دیتابیس مرحلهٔ ۰۰۰۱ می‌سازد و سپس ارتقا می‌دهد. تست مرورگر از دادهٔ صرفاً حافظه‌ای استفاده می‌کند و جای آزمون GUI واقعی Tauri نیست.
